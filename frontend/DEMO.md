# SpotScore 데모 시나리오

4주차 데모용 시연 순서. CLAUDE.md 대시보드 화면 구성(업종 선택 → 랭킹+지도(양방향 연동) → 상세 패널) 흐름을 그대로 따른다.

> 이 문서는 2026-08-07 최종 점검(백엔드 :8080, 프론트 :5173 라이브 상태 + DB 직접 조회로 검증) 시점 기준으로 갱신됨. 이전 버전은 "강남구 역삼1동/역삼2동 파일럿" 단계를 전제로 했으나, 지금은 서울 426개 행정동 전체가 이미 수집·계산되어 있다.

## 사전 준비

- 백엔드(`:8080`)가 이미 기동 중이고, DB에는 서울 426개 행정동 × 75개 업종 기준 점수가 이미 계산되어 있음(라이브 확인: `score_cache` 26,637행, 75개 업종 전부 데이터 보유). **배치를 새로 돌릴 필요 없음.**
- 프론트는 반드시 `http://localhost:5173`에서 실행(Kakao Map JS 키가 이 도메인으로 제한되어 있어 다른 포트에서는 지도가 안 뜸).
- 좌표는 426개 전 지역 시딩 완료 — 지도에 마커가 안 뜨는 지역 없음.
- (참고, 시연에는 불필요) DB를 초기화한 새 환경에서 처음부터 재현하려면: `POST /api/v1/admin/regions/discover-seoul` → `/rebuild-crosswalk` → `/seed-coordinates` → `SPOTSCORE_BATCH_TARGET_REGIONS`를 서울 전체로 넓혀 `/api/v1/admin/batch/run` → 가중치/로직 변경분 반영을 위해 `/api/v1/admin/scores/recalculate`. `application-dev.yml`의 기본값(`target-regions`)은 아직 역삼1동/역삼2동 파일럿 2개 동으로 남아있으므로 환경변수 오버라이드가 필요하다.

## 시연 순서 (약 5분)

1. **업종 선택** (30초) — 업종 선택 전 화면을 먼저 보여준다: 랭킹 사이드바엔 "업종을 먼저 선택해주세요.", 지도엔 "점수는 지역만으로는 계산되지 않고, 지역 × 업종 조합에서만 산출돼요."라는 안내만 뜬다 — 필수 선택 흐름과 "점수는 지역×업종 조합에서만 나온다"는 핵심 원칙을 여기서 짚고 시작한다.
   - 드롭다운은 기본으로 추천 업종 30개(실제 업소 수 상위)만 보여주고, "전체 업종 보기"를 누르면 75개 전체가 "추천 업종"/"전체 업종" 두 섹션으로 나뉘어 뜬다는 것도 짧게 언급.
   - "한식" 선택.
2. **랭킹 확인** (30초) — 왼쪽 랭킹 리스트에 424개 지역이 점수 내림차순으로 뜨는 것 확인(둔촌1동 1개 동만 인구 표본 부족으로 제외되어 424/425). 1위 지역 점수가 왜 높은지는 아직 말하지 않고 다음 단계로 넘어감(궁금증 유발).
3. **지도 확인** (1분) — 지도에 랭킹과 동일한 지역이 점수 배지로 찍혀 있는 것 확인. 업종을 고르면 그 업종 데이터가 있는 지역 범위로 지도가 자동으로 맞춰진다(전국 기본 줌에서 서울 권역으로). 랭킹 리스트에서 지역을 클릭하면 지도가 해당 지역으로 이동/확대되고, 반대로 지도 배지를 클릭하면 랭킹 리스트에서 해당 행이 하이라이트되는 양방향 연동을 직접 클릭해서 보여준다.
4. **"왜 이 점수인가" 설명 (상세 패널)** (2~3분) — 1위 지역을 클릭해 상세 패널을 연다.
   - 상단 등급 배지("🏆 상위 1% 이내 · 매력적인 입지")부터 짚는다 — "종합 점수는 배치가 바뀔 때마다 절대 숫자가 흔들리므로, 같은 업종 안에서의 상대 순위(퍼센타일)로 등급을 매긴다"는 설계 의도를 설명.
   - 종합 점수를 크게 보여주고, 바로 아래 "수요"/"공급" 두 카드로 시선을 옮긴다. 수요 카드는 인구 규모+가구 구조 막대그래프와 원자료(총인구/인구밀도/가구 수/평균 가구원 수), 공급 카드는 경쟁 여유도 막대그래프와 원자료(동일 업종 업소 수, 인구 1만명당 업소 수, 기준일)를 보여준다.
   - 각 카드 하단의 가중치 안내 문구("이 지역·업종 조합에는 수요 50% · 공급 50% 가중치가 적용됐어요")도 짚는다 — 가중치가 코드에 박혀있지 않고 API로 조회된다는 점.
   - 순위가 낮은 지역도 하나 클릭해서 브레이크다운이 반대로 나오는 것(예: 인구 규모는 높은데 경쟁 여유도가 낮아 종합 점수가 밀린 경우)을 대비시켜 보여주면 "종합 점수 하나만 보지 않고 브레이크다운을 봐야 하는 이유"가 자연스럽게 전달된다.
5. **엣지 케이스 짚기 (선택, 시간 남으면)**:
   - 아직 배치가 안 돈 업종을 선택하면(현재 75개 업종 전부 데이터가 있어 실제로 재현은 안 되지만) "아직 집계된 데이터가 없습니다" 문구가 뜬다는 것을 말로 설명 — 이게 "0점"이 아니라 "데이터 자체가 없음"이라는 것.
   - **인구 표본이 너무 작은 지역(둔촌1동, 인구 19명)은 이 화면에서 직접 클릭해 보여줄 수 없다** — 밀도 이상치가 다른 지역 순위를 왜곡하지 않도록 랭킹/지도 양쪽에서 아예 제외되기 때문(의도된 설계). 대신 Swagger UI(`/swagger-ui.html`)나 curl로 `GET /api/v1/scores/detail?regionCode=11740690&industryCode=G204`를 직접 호출해 `totalScore`/`densityScore`가 `null`로, `populationStat.totalPopulation`이 19로 오는 것을 보여주면 "0점이 아니라 산출 대상에서 제외됐다"는 설계를 라이브로 증명할 수 있다.

## 예상 질문 대비 요약

1. **"왜 이 가중치인가?"** — 인구 규모:가구 구조 = 3:1(인구 규모가 시장 절대 크기를 나타내는 1차 지표, 가구 구조는 세부 보정용 2차 지표). 수요:경쟁여유도 = 1:1 — 경쟁 여유도 자체가 이미 인구 대비로 계산돼 수요 정보를 내부에 포함하고 있어서, 한쪽에 임의로 비중을 더 주려면 매출 상관관계 같은 데이터 근거가 필요한데 확보하지 못했다. 근거 없는 편향을 주지 않는 게 가장 방어 가능한 선택이라 1:1로 재산출했다(AHP 쌍대비교 2단계).
2. **"경쟁 여유도가 왜 이렇게 표현되나?"** — 업소 "개수"가 아니라 인구 대비 밀도의 순위(퍼센타일)로 계산한다. 원래는 인구 대비 밀도를 min-max로 정규화했는데, 인구가 극단적으로 적은 지역(둔촌1동, 19명) 하나가 전체 스케일을 왜곡하는 문제가 발견됐다. 순위만 반영하는 퍼센타일 방식으로 바꾸고, 인구 100명 미만 지역은 아예 그 업종의 경쟁 여유도 산출 대상에서 제외해(값을 0으로 억지로 만들지 않고 "데이터 부족"으로 표시) 이상치가 다른 지역들의 순위에까지 영향을 못 주게 막았다.
3. **"매출 데이터는 왜 없나?"** — 실증적으로 절대 점수 기준선을 만들 수 있는 방법이라 검토는 했지만, 전국 커버리지가 있는 매출 데이터(소상공인365)가 iframe 전용이라 원천 데이터 접근 자체가 불가능함을 확인했다(2026-08). 지금은 퍼센타일 기반 상대 등급(상위 10%/30%/70% 구간)으로 대체했고, 매출 데이터 확보 시 실증적으로 재조정할 수 있는 확장 여지로 남겨뒀다.

## 알아두면 좋은 제약 (질문 대비)

- 인구 표본이 100명 미만인 지역(현재는 둔촌1동 1곳)은 경쟁 여유도/종합 점수를 아예 산출하지 않는다. 랭킹·지도에도 나타나지 않아 "조용히 빠지는" 형태이며, 상세 API를 직접 호출하면 `null`로 명시적으로 온다(0점 아님).
- 상권정보 매핑이 원천적으로 실패한 지역(용신동 1곳)은 REGION 테이블엔 존재하지만 store_count/score_cache 자체가 없다 — 어떤 업종을 골라도 랭킹/지도/상세 어디에도 나타나지 않고, 상세를 직접 호출하면 404가 온다. 매핑 실패 원인은 파악됐고(SGIS-상권정보 코드 체계 불일치) 재조사 중인 알려진 이슈다.
- 가중치(수요/공급/인구·가구 비율)는 `SCORE_WEIGHT_CONFIG` 테이블 값으로, 코드 수정 없이 `PUT /api/v1/admin/score-weights/{weightKey}`로 조정 가능하다. 단, 값만 바꾸면 화면엔 즉시 반영 안 되고 `POST /api/v1/admin/scores/recalculate`로 SCORE_CACHE를 다시 계산해야 한다.
- `/api/v1/admin/**` 엔드포인트는 전부 인증이 아직 없다(로컬 전용, 운영 배포 전 추가 예정 TODO로 코드에 명시돼 있음) — 데모/내부 용도로만 노출.
